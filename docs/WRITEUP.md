## 1. Insights & Failures (25 pts)

The scoring rule, not the model, set the design. Per `rules.md`, a
constraint-and-objective task scores each deliverable item as
`s = 0.4p + 0.6·G·O'`, with `G = 1` only when **every** hard constraint is met.
Compliance therefore caps at `0.4p`; the `0.6` term is paid only for a design
that beats its naive baseline. Four findings shaped the harness:

- **Declared-path discovery was blind.** The path regex had no `zip` or `py`, and
  a `.strip("./")` removed the leading slash, so `/filesystem/.../submission.zip`
  was read as workdir-relative and never resolved. Counted from
  `eval/dev_set.yaml`: 14 of 29 dev tasks deliver a folder, 12 a
  `submission.zip`, 2 a `.py`, 1 an `.ifc`. The gate was reading almost none of
  them.
- **Discovery never left the workdir.** `find . -maxdepth 3` cannot see
  `/filesystem`, where a dozen dev tasks write their package. Now a marker is
  written at task start and discovery unions
  `find /app /filesystem -type f -newer`.
- **Unconditional gates were the largest defect.** A one-line smoke task — write
  a file containing `HELLO` — was failed twice for carrying no claims block and
  no revision table, and four model rounds were spent demanding artefacts nobody
  asked for. Gates now declare `applies(ctx)` and decline what they cannot judge.
  Effect on that task: **5 requests and 4 repair rounds → 2 requests and 1**.
- **The verdict was contaminating graded output.** `artifacts.md` exports
  `final_message.md` per task, and 14 of 29 dev tasks are graded with it. The
  gate status now goes out as a `log` frame; the summary carries the agent's
  words only.

**Two things that failed or surprised us.** First, *"a gate that always runs is
the safe choice."* It is not: a false positive costs more than a missed check,
because the repair loop pushes the agent to edit a deliverable the rubric already
scores, to satisfy a check the grader never asked about. Second, *"discovering
deliverables once, before the agent runs, is enough."* It gates an empty folder
and fails every check vacuously; discovery has to follow each turn.

## 2. Architecture & Reasoning (25 pts)

Figure 2 (`docs/figures/architecture.png`): `serve.py` holds a protocol-v1
WebSocket; `harness.py` runs the agent turn, executes tool calls through the
evaluator, then re-reads the artifacts and runs the gate registry. Six invariants
are enforced in code, not in prompt text:

1. **Authority separation** — the judge never reads the model's summary.
2. **Re-derivation** — `_collect` re-opens every deliverable and extracts its
   text (folders enumerated, zips opened, `.docx`/`.xlsx` parsed as XML with the
   standard library) before any check runs.
3. **Strict pass** — `all_hard_pass([])` is `False`; a gate that raises becomes a
   hard failure, never a silent success.
4. **Signed failure** — `(gate_id, cause_code, observed, limit, unit)` plus a
   stable signature, so two failures with equal magnitude but different causes
   never share a lesson.
5. **Conditional memory** — lessons live outside the context window, at most one
   per repair round, admitted only on a verified fail→pass flip.
6. **Bounded repair** — finite rounds, then stop.

**One dev task against an engineer's workflow — `lv-cable-sizing`.** Its declared
deliverable is a `submission.zip` under
`/filesystem/electrical__lv_cable_sizing__blind/output/`. An engineer sizes the
feeder from load, applies the code's continuous-load factor, checks voltage drop
per segment and then cumulatively across the run, and issues a package. The
harness mirrors that mechanically: it resolves the declared path, opens the
package, reads the calculation text, and requires the claims block to carry the
inputs with declared units so the gate can recompute ampacity at 1.25×, the
per-segment drop against 3%, and the cumulative drop against 5% — rather than
trusting the narrative. A takeoff that rounds down is a hard failure, not a
style note.

## 4. Efficiency & Scaling (20 pts)

Figure 3: score vs cost — `{{FIGURE_3}}`.

Design choices that bound cost: repairs are round-budgeted rather than
token-budgeted; one lesson is injected per round, never a growing transcript of
everything that ever failed; `MAX_STEPS_PER_ROUND` caps tool misuse inside a
turn; the model is reachable only through the egress proxy, so the only reachable
host is the model endpoint. Token usage is reported per call through `usage`
frames, which is what makes the cost column in §1.2 measured rather than
estimated.
